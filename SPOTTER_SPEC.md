> **An AI research booth for live football commentary.**
> Specialist agents watch a live (synthetic) match, propose verified insight cards, a Producer agent decides what airs and when, and AI voices deliver play-by-play and color commentary — personalized by language, audience, energy and club perspective, with a human showrunner in control.

## 1. Product

### User & problem
- **User:** a broadcaster's commentator / showrunner.
- **Problem:** commentators prep stacks of notes and still miss live insights; many markets and languages get no commentary at all.
- **Spotter:** in broadcasting, a "spotter" feeds facts to the commentator. Here, a team of AI agents is the spotter. The human either speaks himself (cards are his notes) or lets the AI voice narrate for his chosen audience.

### Pitch line
*"Your commentator covers one language. Spotter covers every market — and does his research for him."*

### The five brief stages, mapped
| Stage | Where in Spotter |
|---|---|
| Ingest | Live event stream → match state, 2D pitch |
| Interpret | Stats engine (pass difficulty, speed, control/chaos, xG) |
| Explain | Proposer agents write "why it matters" cards; Verifier checks them |
| Render | Pitch, Kanban board, subtitles, synchronized voice |
| Personalize | Left panel: language, audience, energy, tone, club perspective, player focus, chat directives |

## 3. Architecture

```
               ┌──────────────────────── Backend (FastAPI, asyncio, one process) ───────────────────────┐
 data/*.json → │ MatchClock ──► Event stream ──► StatsEngine ──► MatchState (shared)                     │
               │                     │                               ▲                                   │
               │                     ▼                               │ tools read                        │
               │               Dispatcher (code) ── wakes ──► Proposer agents (concurrent)              │
               │                     │                 Stats Scout · Tactical Analyst ·                 │
               │                     │                 Dossier Researcher · Storyline Keeper            │
               │                     │                               │ write cards                       │
               │                     │                               ▼                                   │
               │                     │                        BOOTH BOARD (shared blackboard)            │
               │                     │                               │                                   │
               │                     │        Card lifecycle: Verifier → Producer fit → Narrator → TTS   │
               │                     │        (rejected → back to proposer once)                         │
               │                     │                               │                                   │
               │                     └──► Caller (play-by-play, 2s lookahead) ──► TTS                    │
               │                                                     │                                   │
               │                         Producer scheduler (quiet windows, ranking, TTL, say-now)       │
               │                                                     │                                   │
               └────────────────────────────── WebSocket + REST ─────┼───────────────────────────────────┘
                                                                     ▼
                                   Frontend (React): pitch rendered 2 s behind server clock,
                                   board, controls, audio player, subtitles
```

### Patterns (say these in the README)
- **Blackboard pattern:** agents never call each other. They read `MatchState` and the `BoothBoard`, and write cards to the board.
- **Event-driven, concurrent proposers:** the Dispatcher wakes only relevant agents per event, with cooldowns.
- **Producer as orchestrator:** decides fit per audience, ranks, times cards into quiet moments, expires stale ones, adapts to human directives.
- **Independent Verifier:** code recomputes every numeric claim; a small model checks qualitative claims.
- **Broadcast delay:** backend runs 2 s ahead of what the screen shows, so AI play-by-play lands in sync.
- Implement the card lifecycle (Verifier → Producer-fit → Narrator → TTS, with the conditional edge back to the proposer on rejection) as a **Microsoft Agent Framework workflow** if the current API supports it cleanly; otherwise as an asyncio pipeline. Proposers are Agent Framework agents with function tools.

### 5.7 Generator rules (`generator/generate.py`, seed=42)
- Script beats (§5.5) are **anchors**; between anchors, simulate possession chains using team style params and player attributes.
- **Positions:** each team holds formation slots; slots shift toward the ball and by phase (attacking/defending), with compactness and noise; ball carrier is at the event location. Frames must be plausible for smooth interpolation (no teleporting > ~10 m between consecutive events unless time gap allows it at ≤ 9 m/s).
- Respect substitutions and the red card: no events from players off the pitch; 10 v 11 after 61'.
- Include quiet moments naturally: throw-ins, goal kicks, fouls/free kicks, subs, injury stoppage, VAR, goal celebrations.
- **Realism targets:** 450–600 passes per team; 78–89% pass accuracy; 10–18 shots per team; sprint speeds up to 34–35 km/h; shot speeds 60–120 km/h; possession roughly 55/45 Redmoor in the 1st half, swinging after the red card.
- **History:** simulate 10 matchdays (summary level for other teams, full player stat lines for RED/WHI) so the table matches §5.2, then enforce pinned facts, then **recompute all aggregates from the lines**.
- `generator/validate.py` must assert: score progression, subs/cards/VAR/penalty per script, pinned facts, realism ranges, positions inside the pitch, no events from off-pitch players. Print a short realism report.

## 6. Stats engine (`stats/`)

Incremental: consumes events in order; supports fast rebuild up to any time (for seek).

| Metric | Definition |
|---|---|
| Possession % | Time-weighted between possession changes; rolling 5 min + match |
| Passes / accuracy | Per team & player |
| Pass distance | Euclidean, metres |
| **Pass difficulty (0–100)** | 25·norm(distance, 0–45 m) + 25·norm(forward progress toward goal, 0–30 m) + 20·pressure (under_pressure, + opponents within 3 m of receiver /3) + 20·norm(opponents bypassed between start.x and end.x, 0–4) + 10·target zone (final third 0.5, box 1.0) |
| Ball / shot speed | From event fields |
| Distance covered, top speed, sprints | From frame deltas; sprint ≥ 25 km/h |
| xG | Simple logistic on distance & angle; header ×0.7; penalty 0.76 |
| **Control index** | Per team, rolling 5 min, sums to 100: weighted possession share, territory (share of events in opponent half), relative pass completion, xG share |
| **Chaos index (0–100)** | Rolling 5 min: turnovers/min, possession switches/min, shots (both teams)/min, fouls/min. **Calibrate** so 1'–15' < 35 and 78'–86' > 75 |
| Duels | Per player pair (e.g. Moretti vs Whitaker: attempts, won) |
| Alerts | Threshold crossings: top speed > 33 km/h, shot speed > 100 km/h, distance milestones (5/10 km), season-best, first goal, milestones (e.g. 50th pass) |
| Win probability | Simple formula: score diff, time left, men on pitch, rolling xG rate |
| **Quiet windows** | From restarts/stoppages, estimated length: throw-in 6 s, goal kick 8 s, free kick 12 s, corner 15 s, sub 25 s, card 20 s, goal celebration 40 s, injury 40 s, VAR 60 s, half-time ∞ |

### 7.1 Shared card schema
```json

  "created_t": 3794.2,

  "evidence_event_ids": [102, 233, 410, 655, 790],
  "priority": 4,                           // 1-5 (proposer's view)
  "time_sensitive": true,
  "ttl_s": 30,                             // expires if not aired (background cards may use 300)
  "status": "proposed",                    // see lifecycle
  "verifier": {"ok": null, "reason": null, "revision_of": null},
  "producer": {"fit": null, "reason": null, "score": null},
  "render": {"line": null, "language": null, "audio_url": null, "duration_ms": null}

```
**Lifecycle:** `proposed → verifying → (rejected → revising → verifying) → verified → (skipped | queued) → rendering → ready → airing → aired`; terminal also: `expired`, `removed`, `discarded` (failed twice).

### 7.2 Dispatcher (code, not an agent)
Maps events to wake-ups, enforces per-agent cooldowns (match seconds), skips muted agents, caps concurrency, respects `MAX_LLM_CALLS_PER_MIN`.

| Agent | Wake on | Cooldown |
|---|---|---|
| Stats Scout | shot, goal, card, sub, stats alert, every 3 match-min | 45 s |
| Tactical Analyst | every 5 match-min, control swing > 12 pts, red card, sub, goal | 90 s |
| Dossier Researcher | player's first key involvement (shot, key pass, final-third touch), sub on, goal, card, focus player set | 60 s |
| Storyline Keeper | goal, card, repeated duel pattern (≥3), every 10 match-min | 90 s |

### 7.3 Proposers (gpt-5-mini, low reasoning, JSON output = card schema)
Common rules in every system prompt: write **one neutral English fact card** (≤ 30 words), explain *why it matters* when relevant, include structured `claims` for every number, include evidence event ids, check the board (`get_recent_cards`) to avoid repeating aired content, return `null` if nothing is genuinely worth saying. No tone, no language adaptation (that's the Narrator's job).

| Agent | Purpose | Tools |
|---|---|---|
| **Stats Scout** | Notable numbers, milestones, thresholds | `get_player_stats(id, window)`, `get_team_stats(team, window)`, `get_match_leaders(metric)`, `get_alerts(since_t)`, `get_recent_cards()` |
| **Tactical Analyst** | Shifts in control/pressure/shape, and *why* | `get_control_chaos(window)`, `compare_periods(a, b)`, `get_pressure(team, window)`, `get_average_shape(team, window)`, `get_player_matchup(a, b)`, `get_win_probability()`, `get_recent_cards()` |
| **Dossier Researcher** | Context outside this match | `get_player_dossier(id)`, `get_team_dossier(team)`, `get_head_to_head()`, `get_league_table()`, `get_player_stats(id, "match")`, `get_recent_cards()` |
| **Storyline Keeper** | Threads within this match | `get_key_moments()`, `get_duels(a, b)`, `get_player_timeline(id)`, `get_aired_history()`, `get_recent_cards()` |

All tools read `MatchState` / data files. Implement them once in `tools/match_tools.py` (optionally also expose via MCP).

### 7.4 Verifier
1. **Code checks (milliseconds):** recompute every `stat` claim from the stats engine/dossiers (tolerance ±1 for counts, ±2% for percentages, ±0.5 km/h for speeds); check evidence ids exist; dedupe against aired cards.
2. **Qualitative check (gpt-5-nano)** only for text not covered by claims: "Is this statement supported by this evidence? Answer JSON {ok, reason}."
3. On fail: status `rejected` with reason → proposer gets one revision attempt with the reason → second fail = `discarded`. Show red flash + "revised" link on the board.

### 7.5 Producer (orchestrator)
- **On verified card:** gpt-5-nano audience-fit call with instance settings + active directives → `{fit, reason, priority_adjust}`. Not fit → `skipped` (shown greyed with the reason, e.g. "too technical for casual fans").
- **Ranking loop (code, every 500 ms):**
  `score = 10·priority + relevance + directive_boost − age_decay − diversity_penalty`
  - `relevance`: +25 if a card's player is involved in the last ~10 s of events (on the ball / in the duel); +10 if same team in possession in final third.
  - `directive_boost`: e.g. focus player +30, "more tactics" +15 to tactical cards.
  - `diversity_penalty`: same agent or same player aired in the last 60 s.
  - Cards past TTL → `expired`.
- **Airing:** when a quiet window starts, pick the top `ready` card whose `duration_ms` fits the window (or the top card if the window is long). **⚡ Say now** = air right after the current line. **✕** = `removed`.
- **Directives:** chat text → gpt-5-nano parses into `{type: focus_player | more_topic | less_topic | avoid_topic | mute_agent, target, expires_t}`; stored in shared state; Producer and proposers read them. Shown as chips.
- **Adaptation:** if the human removes ≥3 cards of one category within 5 match-minutes, auto-add a `less_topic` directive (shown as a chip so it's visible and removable).

### 7.6 Narrator (gpt-5-mini)
- Triggered when a card becomes `queued` (pre-render early) and re-run if instance settings change.
- Rewrites the neutral card into **one spoken line** (≤ 25 words) for: language, audience (casual/analyst), energy (1–5), tone, club perspective (neutral / Redmoor fans / Whitcliffe fans), focus player.
- Must keep every number from `claims`. Code checks numbers in the output; mismatch → retry once → else speak a plain version (EN) / skip (AR).
- Subtitle: if language is Arabic, subtitle = the original English card text.

### 7.7 Caller — play-by-play (gpt-5-nano; mini if Arabic quality is weak)
- Runs on **phases of play** inside the 2 s lookahead window: group upcoming events (e.g. a passing move ending in a shot) into one call.
- Speaks on: shots, goals, saves, big chances, final-third attacks, fouls, cards, penalties, VAR, subs, kickoff, half/full time. Quiet passing spells → occasional short connector or silence.
- Prompt includes instance settings and the **last 10 spoken lines** ("do not reuse these phrasings"). ≤ 15 words (goals may be longer).
- **Deadline 1.4 s** → fallback to a template from `templates_{lang}.json`. Templates are generated once by `scripts/make_templates.py` (many variants per event type × energy level × language) and committed.
- Each line is tagged `play_at_t` = display time of its event, so audio lands in sync with the pitch.

### 7.8 TTS (`speech/tts.py`)
- Azure Speech SDK, SSML with `<prosody rate pitch>` mapped from energy (1 calm → 5 hype).
- Output mp3, cached by hash(text + voice + prosody), served at `/api/audio/{id}.mp3`.
- Failure → line delivered as subtitle-only (`audio_url: null`).

## 8. Timing & audio scheduling
- **MatchClock** on the server: speed 1×/2×/5×, pause, seek(minute). The frontend displays events at `server_t − 2.0 s` (scaled by speed).
- **Seek:** clear board queue and audio, rebuild stats to that time, agents resume with "match so far" context.
- **Audio scheduler (server decides, client plays):**
  1. Caller lines (priority; drop if > 3 s stale).
  2. ⚡ Say-now cards (next after the current line).
  3. Cards only in quiet windows.
  4. Never overlap; client plays `speech` messages at `play_at_t`.
- At 5× speed: Caller limited to goals/shots/cards; Narrator still works but fewer cards air.

## 12. Failure recovery (make each visible in the board/trace)
1. Verifier rejects → proposer revises once → else discarded.
2. Caller misses the 1.4 s deadline → template line.
3. Agent error/timeout → status `error`, Dispatcher backs off; other agents continue.
4. Card TTL passes → expired.
5. TTS fails → subtitle-only.
6. 429 / rate limit → one retry with backoff → Producer degrades to code-only ranking (fit = true).
7. Narrator changes a number → retry → fallback.
8. Cost cap reached (`COST_CAP_USD`) → all LLM/TTS calls stop; Caller uses templates, cards show as subtitles only, proposers pause; UI shows a "cost cap reached" badge.

## 13. Cache & demo mode
- `CACHE_MODE=record`: run the match; store every LLM response (key = agent + event window + settings hash) and every audio clip on disk.
- `CACHE_MODE=replay`: use cached outputs; on miss, call live.
- Deployed app runs `replay` with a pre-recorded cache for two presets (**EN · Analyst · Neutral** and **AR · Casual · Redmoor fans · energy 5**), so judges get a smooth, cheap demo; other settings go live.
- Global cost guards: `MAX_LLM_CALLS_PER_MIN` (rate) and `COST_CAP_USD` (hard cap, enforced in `backend/app/llm.py`, ledger in `backend/app/data/cost_ledger.json`, see §0.1). Azure budget alerts are delayed and are only a backup.
- Development tips to save cost: develop with AI voice off, test short windows via jump-to-minute, use 5× speed, record the cache once.
